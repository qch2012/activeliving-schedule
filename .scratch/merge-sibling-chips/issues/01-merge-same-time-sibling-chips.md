# 01 — Merge same-time sibling chips

**Status:** done

## Agent Brief

**Category:** enhancement
**Summary:** In the HTML page, collapse sessions that share activity + venue + start + end into one chip / one list row, listing the combined sub-locations.

**Current behavior:**
The page renders one Week-grid chip and one List row per `Session`. When a source
splits one activity across sub-locations for the same time window, the page shows
one chip per sub-location. Real data: `Drop In - Running` at the Kinesiology
Track runs `Kin Track 1-2` and `Kin Track 3-6` as two separate sessions over the
identical `08:00–20:30` block on most days, producing two near-identical chips in
one narrow day column. Rec. Fit / Open Gym occasionally do the same
(`Red Gym` + `Gold Gym`, same time).

**Desired behavior:**
Group the day's kept sessions by the tuple **(activity, venue, start, end)**. Any
group with 2+ members renders as a **single** chip (Week grid) and a **single**
row (List view). The displayed place is the members' sub-locations combined:

- **Numeric lane ranges** — sub-location tails matching `^\d+(-\d+)?$` (after the
  usual venue-prefix strip): parse to integer intervals, merge
  overlapping/adjacent runs, format each back as `lo-hi` (or `lo` when a single
  lane), join with `", "`. `1-2` + `3-6` → `1-6`; `1-2` + `5-6` → `1-2, 5-6`;
  `1-2` + `2-4` → `1-4`.
- **Otherwise** — take the per-member rendered place strings, dedupe preserving
  first-seen order, join with `", "`. `25m` + `50m` → `25m, 50m`;
  `Red Gym` + `Gold Gym` → `Red Gym, Gold Gym`.
- A `"<venue> / "` prefix shared by all members is shown once
  (`Kin Track / 1-6`). Standalone sub-locations that render without a venue
  prefix when alone must still render without one when merged.
- Merge **only** when every member has a non-empty sub-location; if any member
  has none, render the group unmerged (one chip per member, as today).

The representative session (first in the group after the existing sort) supplies
activity, time, category, and chip colour. `data-cat` and the colour slug are
unchanged — a group shares one activity.

Ordering of chips/rows within a day is unchanged from today's sort
(`(start, end, activity)` for the grid, `(start, end, activity, venue)` for the
list), keyed on the representative session.

**Key interfaces:**
- The render module builds calendar chips via a `_chip(Session)`-style helper and
  List rows via a `_row(Session)`-style helper, both iterating per-day session
  lists. Introduce a grouping step upstream of both that yields render units
  (representative `Session` + combined place string); pass the combined place
  into the chip/row helpers (e.g. an optional `place` override parameter).
- Place text currently flows through a `_place(Session) -> str` helper that
  shortens the venue, strips a venue prefix off the sub-location, de-caps SHOUTY
  text, and passes through standalone sub-locations. Reuse it per member, then
  combine the resulting strings.
- Add a small pure function `list[str] -> str` for the sub-location combination
  (interval merge for all-numeric tails; ordered-dedupe join otherwise).
- `select()` in the model layer, `_uid()`, and `ics_feed()` are **not** touched.

**Acceptance criteria:**
- [ ] A day with two `Drop In - Running` sessions at the same start and end,
      sub-locations `Kin Track 1-2` and `Kin Track 3-6`, renders **one** Week-grid
      chip showing `Kin Track / 1-6` — the page does not contain a
      `Kin Track / 1-2` chip that day.
- [ ] The same day's List view shows **one** row ending `Kin Track / 1-6`.
- [ ] Two sessions with the same activity/venue but different `end` times are
      **not** merged — two chips, two rows.
- [ ] Non-contiguous lanes `1-2` and `5-6` (same time) render as one chip
      `Kin Track / 1-2, 5-6`.
- [ ] Two same-time `Open Gym` sessions with standalone sub-locations `Red Gym`
      and `Gold Gym` render as one chip listing both (`Red Gym, Gold Gym`),
      consistent with how each renders alone (no `Kin Gym /` prefix).
- [ ] A session with no same-time sibling renders byte-for-byte as before; the
      existing `test_render.py` suite passes unchanged.
- [ ] `schedule.ics` still emits one VEVENT per underlying sub-location session
      (verify the existing `.ics` tests still pass and event count is unchanged).
- [ ] New tests cover: the lane merge, the no-merge-on-different-times case, the
      non-contiguous `1-2, 5-6` case, and that the `.ics` feed is unmerged.

**Out of scope:**
- Merging sessions with different start or end times, even overlapping ones.
- Merging across venues or across activities.
- Any change to `.ics` output or UID scheme.
- Collapsing the `cat-run-track` / `cat-run-oval` chip colours.
- A user-facing control to toggle merging.

**Implemented 2026-09-03.** In `alsched/render.py`:

- `_units(sessions)` groups a day's sessions by `(activity, venue, start, end)`
  and yields `(representative session, place string)` pairs. Groups of 2+ merge
  only when every member has a sub-location not in `SUBLOCATION_HIDE`; otherwise
  each member renders on its own.
- `_merge_places(places)` factors a shared `"<venue> / "` prefix, collapses
  all-numeric tails via `_merge_ranges` (contiguous/overlapping runs joined,
  gaps kept as a comma list), and otherwise does an ordered de-duped join.
- `_chip` / `_row` take an optional `place` override; the Week grid and List
  view both feed them through `_units`.
- `select()`, `_uid()`, `ics_feed()` untouched — the `.ics` feed still emits one
  VEVENT per sub-location session.

Tests added to `tests/test_render.py`: lane merge, no-merge on different times,
non-contiguous `1-2, 5-6`, standalone `Red Gym, Gold Gym` (no venue prefix),
`.ics` not merged. Full suite: 40 passed.
