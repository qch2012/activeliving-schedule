# Merge same-time sibling chips

**Category:** enhancement
**Status:** ready-for-agent

## Problem

On the calendar page, when the schedule splits one activity across sub-locations
for the same time window, the page renders one chip per sub-location. The common
case is the Kinesiology Track: `Kin Track 1-2` and `Kin Track 3-6` frequently run
the identical `08:00–20:30` block, so the day column shows two chips that differ
only by lane range. In the current 4-week horizon this happens on 9 day-columns
for Track running (plus 1 for Open Gym, Red Gym + Gold Gym). It's visual clutter
in an already-cramped column.

## Desired

Collapse `Session`s that share **activity + venue + start + end** into a single
chip (Week grid) and a single row (List view), listing the combined
sub-locations.

Sub-location combination:

- **Numeric lane ranges** (`N` or `N-M`): merge into sorted integer intervals,
  collapse contiguous/overlapping runs, format back. `1-2` + `3-6` → `1-6`;
  `1-2` + `5-6` → `1-2, 5-6`.
- **Anything else** (`25m`, `Red Gym`): ordered dedupe, join with `, `.
  `25m` + `50m` → `25m, 50m`; `Red Gym` + `Gold Gym` → `Red Gym, Gold Gym`.
- A shared `"<venue> / "` prefix is shown once: `Kin Track / 1-6`.
- Merge only when **every** group member has a sub-location. If any member has
  none, leave the group unmerged.

Category, chip colour, and the activity filter are unaffected — a group shares
one activity, so `data-cat` and the colour slug are unambiguous.

The `.ics` feed is **display-only unaffected**: it still emits one VEVENT per
underlying sub-location session.

## Decisions (from triage grilling, 2026-09-03)

- Merge rule applies to **any** same-time sibling sessions, not just track lanes.
- Applies to **both** the Week grid and the List view.
- Non-contiguous numeric ranges render as a **comma list** (`1-2, 5-6`), not a
  min–max span.
- `.ics` untouched (each lane space is a real session; the event UID is keyed on
  sub-location).

## Out of scope

- Merging sessions with different start or end times, even if they overlap.
- Merging across venues or activities.
- Any change to `.ics` output.
- Collapsing the two Run chip colours (`cat-run-track` / `cat-run-oval`).
- A user-facing toggle for the merge.
